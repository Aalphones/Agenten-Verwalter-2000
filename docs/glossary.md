# Glossar

Ein Begriff = eine Bedeutung. Code, Doku und Oberfläche verwenden diese Begriffe konsistent. Englische Bezeichner im Code, deutsche Erklärung hier. Neue Fachbegriffe werden ergänzt, sobald sie abgeklärt sind.

| Begriff | Bedeutung |
|---|---|
| **Vorhaben** | Eine Aufgabe (z. B. „Plan XYZ umsetzen“) mit ihren Repositories, ihrem Workspace und ihren Sessions. Die zentrale Einheit der App. Im Code `project` ([ADR 011](decisions/011-vorhaben-und-sessions.md)). |
| **Übersicht (Vorhaben)** | Hauptansicht eines Vorhabens: TL;DR, Repositories, Sessions, „Neue Session“; Reiter „Übersicht · Changes“. |
| **Session** | Eine Claude-Session innerhalb eines Vorhabens, mit eigenem Agenten, Chat, Kontext und Events; im Vorhaben durchnummeriert (#1, #2 …). Ihre ID ist die Session-ID der Claude-Kommandozeile. |
| **Browser-Zugriff** | Schalter pro Session, der den Agenten mit Claude in Chrome startet (`--chrome`); der Agent bedient dann den echten Chrome des Users mit dessen Anmeldungen. Nur im Claude-Betrieb. Im Code `chrome` ([ADR 030](decisions/030-browser-zugriff.md)). |
| **TL;DR** | Kurzfassung einer Session bzw. eines Vorhabens in drei, vier Zeilen, per Knopf von Haiku erstellt; zeigt, wie viele Einträge seither dazugekommen sind. Im Code `tldr` ([ADR 011](decisions/011-vorhaben-und-sessions.md)). |
| **Retro** | Rückblick über alle Sessions eines Vorhabens: der Verwalter sammelt je Session Befunde (Mini-Retro), der Skill `session-review` wertet sie in einer neuen Session aus. Im Code `retro` ([ADR 028](decisions/028-vorhaben-retro.md)). |
| **Regel-Spur** | Was eine Session über die Regeln des Nutzers verrät: geladene Skills und Hook-Sperren; steht in den Retro-Dateien ([ADR 050](decisions/050-regel-spuren.md)). |
| **Mini-Retro** | Rohbefunde einer Session aus einem Einmal-Aufruf mit Sonnet, ohne Bewertung; alle zusammen ergeben `befunde.md` im Retro-Ordner des Workspace. |
| **Werkzeug-Spur** | Die Werkzeug-Aufrufe einer Session je Nutzer-Auftrag, normalisiert und ohne Modell verdichtet; `spur-<N>.md` im Retro-Ordner ([ADR 062](decisions/062-werkzeug-retro.md)). |
| **Werkzeug-Retro** | Einmal-Aufruf mit Haiku je Session über die Werkzeug-Spur: Ziel, Weg, feste Handgriffe, Reibung, Zweck der Inline-Skripte; steht in `werkzeuge.md`. |
| **Repository** | Ein lokales Git-Repository, das in der App bekannt ist (Name, Pfad, Remote). Existiert unabhängig von Sessions. Die App kennt es, sobald es einmal über „Repository hinzufügen“ gewählt wurde; gespeichert ist der Wurzelordner. Auch ein Ordner ohne Git (→ Ordner ohne Git). |
| **RepositoryWorkspace** | Die Verbindung eines Repositorys mit einem Vorhaben: Haupt-Checkout und Basis, für alle Sessions des Vorhabens gleich; bei Sessions vor ADR 010 ein eigener App-Worktree mit Branch. |
| **Worktree** | Ein zusätzliches Arbeitsverzeichnis eines Git-Repositorys mit eigenem ausgecheckten Branch (`git worktree`). Seit ADR 010 legt ihn der Agent an (→ Ticket-Worktree); Sessions davor haben je Repository einen von der App angelegten. |
| **Repository anhängen** | Nimmt ein bekanntes Repository nachträglich in ein Vorhaben auf („+ Repository“ in der Übersicht); gilt für alle seine Sessions. Die Basis der Changes ist der letzte Commit vor dem Anlegen des Vorhabens. |
| **Haupt-Checkout** | Der Ordner, in dem ein Repository auf dem Rechner liegt, mit seinem ausgecheckten Branch — im Gegensatz zu einem Worktree. |
| **Inneres Repository** | Ein Git-Repository direkt in einem angehängten Repository oder Ordner ohne Git (Unterordner mit `.git`-Ordner, eine Ebene tief). Seine Ticket-Worktrees `<Name>-wt-*` liegen daneben im angehängten Ordner. Die Changes zeigen es als `<Repository>/<Name>`, sobald die Reichweite darin etwas committet oder geschrieben hat ([ADR 020](decisions/020-innere-repositories.md)). |
| **Ordner ohne Git** | Ein bekannter Ordner ohne `.git`. Der Agent arbeitet darin wie im Haupt-Checkout; die App hat dort keine Basis, zeigt für den Ordner selbst keine Changes, wohl aber für seine inneren Repositories, und kann nichts zurückholen. Laufwerke, der Benutzerordner und alles darüber sowie der Datenordner der App sind gesperrt. Im Code `RepositoryKind::Folder` / `RepositoryCheckout::Folder` ([ADR 018](decisions/018-ordner-ohne-git.md)). |
| **Ticket-Worktree** | Ein Worktree, den der Agent nach seinen Anweisungen neben dem Haupt-Checkout anlegt, Ordner `<repo>-wt-<Name>` — bei einem inneren Repository im angehängten Ordner (→ Inneres Repository). Die Changes erkennen ihn auch ohne diesen Namen und an anderer Lage (etwa innerhalb des Repository-Ordners), sobald die Session darin eine Datei geschrieben hat: an der `.git`-Datei seiner Wurzel. Er gehört zum Vorhaben, sobald der Agent einer seiner Sessions ihn benutzt hat, und erscheint in den Changes der Session, die ihn benutzt hat, und in der Vorhaben-Übersicht; gemessen gegen den Standard-Branch mit den eigenen Commits (ADR 010, ADR 014). |
| **Session-Branch** | Der Branch `verwalter/<Name>`, den die App für Sessions vor ADR 010 in jedem ihrer Repositories angelegt hat; in allen Repositories einer solchen Session gleich. Neue Vorhaben bekommen keinen: Branches legt der Agent nach seinen Anweisungen an. |
| **Einstellungen** | Werte, die für die ganze App gelten: Farbschema, Betriebsart und lokales Modell sowie die Standardwerte (Modell, Modus, Denkaufwand), mit denen die erste Session eines neuen Vorhabens startet. Gespeichert in der Tabelle `settings` ([ADR 012](decisions/012-einstellungen-farbschema-und-listen.md)). |
| **Betriebsart** | Woher der Agent sein Modell bekommt, für die ganze App in den Einstellungen: Claude (Claude-Abo), Claude Code + LM Studio (dieselbe Claude-Kommandozeile, Modell lokal in LM Studio), Autark (eigener Agent des Verwalters, ohne Claude-Kommandozeile und ohne Anthropic) oder Codex (OpenAI Codex mit dem ChatGPT-Konto). Nicht zu verwechseln mit dem Modus einer Session ([ADR 016](decisions/016-betriebsarten-und-lokales-modell.md), [ADR 017](decisions/017-autarker-agent.md), [ADR 031](decisions/031-codex.md)). |
| **Codex** | Die Betriebsart, in der die Sessions mit OpenAI Codex und dem ChatGPT-Konto des Benutzers arbeiten statt mit Claude; Codex führt seine Verläufe selbst ([ADR 031](decisions/031-codex.md)). |
| **Übersetzer** | Der Unterbefehl `codex` von `verwalter.exe`: spricht nach außen das Zeilenprotokoll der Claude-Kommandozeile, nach innen mit `codex app-server` — so bleibt der Rest des Verwalters für „Codex“ unverändert ([ADR 031](decisions/031-codex.md)). |
| **Autarker Agent** | Der eigene Agent des Verwalters für die Betriebsart Autark: gleiche Werkzeugnamen wie Claude Code, Modell aus LM Studio, Subagenten, Hintergrundprozesse, MCP-Server und Web ohne Anthropic ([ADR 017](decisions/017-autarker-agent.md)). |
| **Lokales Modell** | Ein in LM Studio geladenes Sprach- oder Bildmodell, das in den Betriebsarten Claude Code + LM Studio und Autark die Modellanfragen beantwortet; gewählt in den Einstellungen. |
| **Farbschema** | Dunkel, Hell oder System (folgt Windows); gilt für Inhalt und Titelleiste, gespeichert in den Einstellungen. |
| **Workspace** | Der Arbeitsordner eines Vorhabens; alle seine Sessions teilen ihn. Hier liegen Anhänge (bei Sessions vor ADR 010 auch die App-Worktrees). Arbeitsverzeichnis und Sicherheitsgrenze des Agenten. Liegt unter `<Benutzerordner>\.verwalter\workspaces\<8 Zeichen>`; ändert sich für ein Vorhaben nie. |
| **Workspace Contract** | Die feste Ordnerstruktur, die der Agent sieht: ein Unterordner pro Repository, sonst nichts. |
| **Base ref** | Der Branch, der beim Anlegen der Session im Haupt-Checkout ausgecheckt war (bei losgelöstem HEAD die Commit-ID); angezeigt als „gegen <Basis>“. Gemessen wird gegen `base_commit`, die Commit-ID dieses Stands. Pro RepositoryWorkspace. Bei einem nachträglich angehängten Repository ist `base_commit` der letzte Commit vor dem Anlegen des Vorhabens. |
| **Committed / Uncommitted** | Änderungen seit der Basis, die bereits als Commit im Session-Branch liegen bzw. nur im Arbeitsverzeichnis (gestagte und untracked Dateien eingeschlossen). Gezählt wird nur, was der Session bzw. dem Vorhaben gehört (ADR 014). |
| **Blickwinkel** (`ChangeScope`) | Welche Änderungen die Changes-Ansicht zeigt: „Alle“ (Basis → Arbeitsverzeichnis), „Uncommitted“ (letzter Commit → Arbeitsverzeichnis, samt gestagten und neuen, nicht ignorierten Dateien), „Committed“ (Basis → letzter Commit). In der Oberfläche das Segment „Alle · Uncommitted · Committed“. |
| **Eigene Changes** (`ChangesReach`) | Was die Changes-Ansicht zeigt: in einer Session nur ihre eigenen Commits und die Dateien, die ihr Agent geschrieben und seitdem nicht committet hat; in der Vorhaben-Übersicht die Summe aller Sessions. Eigene Commits erkennt die App am Zeitfenster der Git-Befehle des Agenten (ADR 014). |
| **Fremde Änderung** | Eine uncommittete Datei im Ordner eines Eintrags der Changes, die nicht zu den eigenen Changes der Session gehört — von Hand, von einer anderen Session oder von einem Programm geändert. Die Git-Werkzeuge zeigen sie getrennt und haken sie nicht von selbst an ([ADR 025](decisions/025-git-werkzeuge.md)). |
| **Verlauf (Git)** | Die letzten 50 Commits des ausgecheckten Branches als Graph in der Übersicht der Changes, dazu die eingehenden Commits aus dem Upstream (`HEAD..<Upstream>`) als eigene Zeile. Nur der aktuelle Branch; eingehende Commits sind so aktuell wie der letzte Fetch ([ADR 025](decisions/025-git-werkzeuge.md)). |
| **Sperre (Git)** | Git-Befehle, die Dateien im Arbeitsordner ändern (Branch wechseln, Pull, Verwerfen, Stash, Merge, Rebase), warten, solange eine Session des Vorhabens arbeitet (`Starting`, `Running`, `Waiting`) — alle Sessions eines Vorhabens teilen die Ordner. Commit, Push und Fetch bleiben frei ([ADR 025](decisions/025-git-werkzeuge.md)). |
| **Agent** | Der externe Coding-Agent-Prozess (z.B. Claude), der in einer Session arbeitet. Die App orchestriert ihn, ist aber nicht selbst der Agent. |
| **Provider** (`AgentProvider`) | Adapter, der einen bestimmten Agenten-Typ startet, steuert und seine Ausgaben in einheitliche Agent-Events übersetzt (Claude, später OpenCode, LM Studio). |
| **Agent-Event** | Ein strukturiertes Ereignis aus dem Agentenlauf oder der App (z.B. `tool.started`, `session.waiting`). Wird im Event Store gespeichert und von der UI in lesbare Zustände übersetzt. |
| **Event Store** | Ursprünglich als Tabelle `events` mit allen Zustandsänderungen einer Session gedacht. Umgesetzt ist er als Tabelle `chat_entries`: eine Zeile je Chat-Eintrag, wie ihn die Oberfläche anzeigt; rohe Agent-Ereignisse werden nicht gespeichert ([ADR 004](decisions/004-persistenz-und-wiederherstellung.md)). |
| **Session-Status** | Zustand einer Session, acht Werte: `starting` (Prozess gestartet, noch kein `system/init`), `running` (Agent arbeitet an einer Antwort), `waiting` (offene Rückfrage oder Rechte-Abfrage), `paused` (nach Pause/Esc oder nach „Agent neu starten“), `completed` (Antwort fertig, Agent wartet auf die nächste Nachricht), `cancelled` (abgebrochen, nimmt keine Nachrichten mehr an), `error` (Prozess unerwartet beendet oder Antwort mit Fehler), `new` („Neu“: Session im Vorhaben angelegt, Agent nie gestartet, kein Verlauf; startet mit der ersten Nachricht). Eine Unterbrechung ist immer `paused`. Arbeitet der Agent in `completed` oder `paused` von selbst weiter (nach dem Ende eines Subagenten oder Hintergrundprozesses), wechselt die Session auf `running`. Nach einem App-Neustart ist eine vorher aktive Session (`starting`, `running`, `waiting`) `paused`; ihr Agent startet mit der nächsten Nachricht neu; `new` bleibt `new`. |
| **Waiting** | Der Agent hat eine Rückfrage oder Rechte-Abfrage gestellt und wartet auf eine Antwort im Chat oder auf der Karte der Station. Eigener Status, prominent in der Session-Liste. |
| **Wartet auf Skript** | Anzeige-Status der Sidebar, kein Session-Status: der Agent hat abgegeben (`Completed`), kein Subagent wartet, und mindestens ein Hintergrund-Befehl (`Process`) ohne erkannte lokale Adresse läuft noch. Der Agent setzt fort, sobald er endet. Ein Dev-Server mit Adresse zählt nicht ([ADR 032](decisions/032-wartet-auf-skript.md)). |
| **Letzte Aktivität** | Zeitpunkt, an dem der User zuletzt gesendet oder der Agent zuletzt abgegeben hat — Rückfrage, fertig oder Fehler. Werkzeug-Aufrufe zählen nicht. Bestimmt die Reihenfolge in der Sidebar ([ADR 019](decisions/019-letzte-aktivitaet-und-ungelesen.md)). |
| **Ungelesen** | Eine Session, deren letzte Aktivität jünger ist als der letzte Blick des Users. Gesehen ist eine Session, solange sie im Chat- oder Changes-Reiter offen ist. |
| **Archivieren** | Blendet ein Vorhaben samt aller seiner Sessions aus der Liste aus (`archived_at` in der Datenbank gesetzt); einzelne Sessions lassen sich nicht archivieren. Der Verlauf bleibt erhalten; bei Sessions vor ADR 010 entfernt die App App-Worktrees ohne offene Änderungen; Haupt-Checkouts und Ticket-Worktrees bleiben immer. Archivierte Vorhaben findet der Archiv-Dialog über Namen und Chat-Text ([ADR 029](decisions/029-archiv-suche.md)). |
| **Wiederherstellen** | Holt ein archiviertes Vorhaben samt aller seiner Sessions aus dem Archiv zurück in die Seitenleiste (`archived_at` wieder leer). Der Verlauf lädt beim Öffnen einer Session, der Agent startet erst mit der nächsten Nachricht; abgebrochene Sessions sind danach wieder schreibbar. |
| **Rückfrage** | Frage des Agenten mit Optionen (AskUserQuestion); mehrere Fragen erscheinen als Ziehharmonika, nur die aktive ist aufgeklappt ([ADR 045](decisions/045-rueckfrage-kasten.md)); beantwortbar im Chat und auf der Karte ihrer Station ([ADR 055](decisions/055-rueckfrage-auf-der-karte.md)). |
| **Notiz (Rückfrage)** | Kurzer Text zu einer Option einer Rückfrage; geht als `<Option> (Notiz: <Text>)` an den Agenten ([ADR 045](decisions/045-rueckfrage-kasten.md)). |
| **Eigene Antwort (Rückfrage)** | Freitext zu genau einer Frage einer Rückfrage; ersetzt bei Einfachauswahl die Wahl ([ADR 045](decisions/045-rueckfrage-kasten.md)). |
| **Rechte-Abfrage** | Der Agent fragt vor einem Werkzeug-Aufruf um Erlaubnis; erscheint im Chat wie eine Rückfrage mit Erlauben/Ablehnen. |
| **Tool-Aktivität** | Die Einzelschritte des Agenten (Datei lesen, Befehl ausführen …). Im Chat standardmäßig eingeklappt zusammengefasst. |
| **Chat-Ansicht** | Hauptansicht einer Session: Gespräch mit dem Agenten, Status, Rückfragen. |
| **Changes-Ansicht** | Prüfansicht eines Vorhabens, erreichbar aus jeder seiner Sessions: die eigenen Änderungen (Session) bzw. die aller Sessions (Vorhaben-Übersicht): Repositories, Dateien und Diffs gegen die Basis, im gewählten Blickwinkel. |
| **Artefakte-Ansicht** | Ansicht eines Vorhabens, erreichbar aus jeder seiner Sessions und der Übersicht: Liste der Artefakte und Vorschau der gewählten Seite; erscheint erst mit dem ersten Artefakt. |
| **Review-Kommentar** | Kommentar zu einer Diff-Zeile, einem Element eines Artefakts oder einem Bereich auf einem Bild; wird in der Eingabeleiste gesammelt und mit der nächsten Nachricht an den Agenten geschickt. Im Code `ReviewComment` mit Ziel `CommentTarget` ([ADR 015](decisions/015-changes-review.md), [ADR 035](decisions/035-kommentare-artefakt-bild.md)). |
| **Lücke** | Unveränderte Zeilen zwischen zwei Änderungen einer Datei, vor der ersten und nach der letzten, als grauer Balken im Diff, aufklappbar: ein Pfeil blendet bis zu 20 Zeilen an seiner Seite ein, der Text im Balken die ganze Lücke, „Ganze Datei“ im Dateikopf alle Lücken („Nur Änderungen“ klappt sie wieder zu). Eingeblendete Zeilen tragen Nummern, Farben und Review-Kommentare wie jede Diff-Zeile. Im Code `gap` ([ADR 043](decisions/043-unveraenderte-zeilen.md)). |
| **Gesammelte Kommentare** | Die noch nicht gesendeten Review-Kommentare einer Session; flüchtig wie der Entwurf, gehen beim Neustart der App verloren. Ihre Zahl steht am Reiter „Chat“. |
| **Bildansicht** | Großansicht eines Bild-Anhangs; dort lassen sich Bereiche kommentieren ([ADR 035](decisions/035-kommentare-artefakt-bild.md)). |
| **Dateiverweis** | Pfad in einer Agenten-Antwort (als Inline-Code oder Markdown-Link), der per Klick mit dem Standardprogramm von Windows öffnet. Nur Anzeige-Formate (HTML, PDF, Bilder, Markdown, Text) und nur innerhalb des Vorhabens; was scheitert, steht in der Fehlerleiste der Session ([ADR 023](decisions/023-dateiverweise-im-chat.md)). |
| **Anhang** | Bild oder Datei, die mit einer Nachricht an den Agenten geht (per Knopf, Hineinziehen oder Einfügen). Liegt nach dem Senden unter `<Workspace>\.anhaenge\`; Bilder bis 3,75 MiB und PDFs bis 10 MiB gehen als Inhalt an den Agenten, alles andere als Pfad. |
| **Skill** | Eine benannte, wiederverwendbare Arbeitsanweisung für den Agenten, aufgerufen als Nachricht, die mit `/name` beginnt. Das `/`-Menü zeigt Skills und Befehle aus `~\.claude\skills`, `~\.claude\commands` und denselben Ordnern der Repositories einer Session; dazu im Abschnitt „Mitgeliefert“ die mitgelieferten Befehle der Betriebsart (ADR 034). Das `/`-Menü sortiert Skills nach Aufrufen der letzten 30 Tage (ADR 039). |
| **Befehl** (Command) | Eine Markdown-Datei in `.claude\commands`, aufgerufen wie ein Skill mit `/name`. |
| **Mitgelieferter Befehl** | Ein `/name`, das der Agent der Betriebsart selbst versteht, ohne Datei: in „Claude“ die Liste der Kommandozeile, in „Autark“ `/compact`, in „Codex“ `/compact` und `/codex-review`. |
| **Modus** | Wie selbstständig der Agent arbeitet: Manuell, Automatisch bearbeiten, Planen, Auto. Pro Session, jederzeit wechselbar. |
| **Denkaufwand** | Wie gründlich das Modell nachdenkt, fünf Stufen von Niedrig bis Max. Pro Session, jederzeit wechselbar. |
| **Artefakt** | Eine Datei oder ein Ordner, den ein Agent für den Menschen im Ordner `.artefakte` des Vorhabens ablegt, um einen Sachverhalt zu veranschaulichen oder zum Ausprobieren anzubieten: Bericht, Dokument, Grafik, Diagramm, Bild, Video, Ton, strukturierte Daten. Anschauungsmaterial, kein Arbeitsergebnis im Repository. Gehört dem Vorhaben; die Liste im Reiter „Artefakte“ gruppiert nach der **anlegenden Session** ([ADR 026](decisions/026-artefakte.md), [ADR 047](decisions/047-artefakte-alle-dateitypen.md)). |
| **Betrachter** | Die Seite, die der Artefakt-Server für Artefakte außer HTML-Seiten und Websites ausliefert (`?view=1`): zeigt den Inhalt je Typ (Text, Markdown, JSON, CSV, PDF, Mermaid, Ordner …) und trägt die Kommentar-Brücke. Läuft wie jedes Artefakt abgeschottet im Rahmen. Lädt eine Bibliothek nicht, zeigt er den Rohtext. PDF rechnet im Hauptthread, weil ein fremder Worker unter der CSP nicht startet. |
| **Zubehör-Ordner** | Unterordner von `.artefakte`, der keine eigene Karte bekommt, weil er zu einer HTML-Seite gehört: sein Name beginnt mit `_`, heißt wie die HTML-Datei daneben ohne Endung oder wird von ihr direkt verlinkt. |
| **Rest-Karte** | Karte im Reiter „Artefakte“ für Dateien, für die es keinen Betrachter gibt (z. B. `.xlsx`): Name, Typ, Größe und „Mit Standardprogramm öffnen“ statt einer Vorschau. |
| **Anlegende Session** | Die Session, die eine Datei in `.artefakte` zuerst angefasst hat; nach ihr gruppiert der Reiter. Ändert eine andere Session die Datei später, steht sie als „zuletzt bearbeitet von“ in der Meta-Zeile. |
| **MCP-Zugang** | MCP-Server des Verwalters auf `127.0.0.1`, über den der Agent einer Session Werkzeuge des Verwalters aufruft (`mcp__verwalter__…`); ein Schlüssel je Session und App-Start bindet jeden Aufruf an deren Vorhaben ([ADR 046](decisions/046-mcp-zugang.md)). |
| **Werkzeug-Satz** | Die Werkzeuge eines Features im MCP-Zugang mit gemeinsamem Präfix (z. B. `artifact_`), angemeldet an einer Stelle (`mcp_access::tool_sets`). |
| **Subagent** | Ein vom Agenten selbst gestarteter Hilfs-Agent für eine Teilaufgabe. Läuft innerhalb der Session, wird dort angezeigt. |
| **Hintergrundprozess** | Ein vom Agenten mit `run_in_background` gestarteter Bash-Befehl, der weiterläuft, während der Agent arbeitet (z.B. ein Dev-Server). Seine Ausgabe schreibt die Kommandozeile in eine eigene Ausgabedatei; die App kann ihn anhalten. |
| **Ausgeführter Befehl** | Ein Bash-Aufruf des Agenten im Vordergrund; steht im Hintergrund-Panel unter „Ausgeführt“ mit Exit-Code und Ausgabe. |
| **Scratchpad** | Ordner einer Session für Arbeitsdateien außerhalb der Repositories (`<Workspace>\.scratchpad\<session-id>`); die App legt ihn beim Start des Agenten an und schreibt ihn ihm per Systemprompt-Zusatz vor ([ADR 022](decisions/022-scratchpad-im-workspace.md)). |
| **Leiste** | Eine der vier seitlichen Flächen mit Griff an der Kante: Seitenleiste, Dateibaum der Changes, Liste der Artefakte, Hintergrund-Panel. Ihre Breite lässt sich ziehen und wird gespeichert (`PanelId`, [ADR 053](decisions/053-verschiebbare-leisten.md)). |
| **Hintergrund-Panel** | Seitenpanel einer Session (440 px) mit den Reitern Prozesse, Subagenten, Scratchpad; geöffnet über den Knopf „Hintergrund“ in der Kopfzeile oder eine Verlaufszeile. |
| **Terminal** | Eine Shell des Betriebssystems (Windows `cmd`, sonst die Login-Shell) in einem Pseudo-Terminal des Core, im Workspace des Vorhabens. Gehört dem Vorhaben, nicht einer Session; höchstens 8 laufende je Vorhaben; nur im Speicher ([ADR 052](decisions/052-terminal.md)). |
| **Terminal-Dock** | Der einblendbare Bereich mit den Terminals des sichtbaren Vorhabens: unten unter der Hauptfläche oder rechts als eigene Spalte (Einstellung „Terminal“); geöffnet über den Knopf `>_` in der Kopfzeile oder `Strg+Ö`. Größe per Ziehkante, unten auch Maximieren. |
| **Kontext-Aufschlüsselung** | Die Liste, was den Kontext einer Session belegt (Systemprompt, Werkzeuge, Memory-Dateien, Skills, Nachrichten, freier Platz). Kommt von der Claude-Kommandozeile; der letzte Stand liegt nur im Speicher des Core. Angezeigt im Fenster der Session-Anzeige in der Kopfzeile. |
| **Kontingent** | Die Nutzungsgrenzen des Abos von Claude bzw. Codex: bei Claude 5-Stunden-Fenster und Woche, bei Codex die Fenster, die Codex meldet (z. B. 30-Tage-Fenster), je mit Prozentwert und Zeitpunkt des Zurücksetzens (englisch „Usage“). Gilt dem Konto, nicht einer Session; angezeigt als „NN %“ im Fuß der Sidebar. |
| **Claude-Konto** | Das Konto, mit dem die Claude-Kommandozeile angemeldet ist (E-Mail, Abo, Organisation). Gehört der Kommandozeile, nicht der App: die App liest es mit `claude auth status` und wechselt es, indem sie `claude auth login` startet. Angezeigt im Abschnitt „Konto“ der Einstellungen; gilt für jeden Agenten, der danach startet ([ADR 021](decisions/021-claude-konto.md)). |
| **MCP-Server** | Ein Programm oder Dienst, der dem Agenten über das Model Context Protocol zusätzliche Werkzeuge gibt (z. B. comfy, Google Drive). Die Claude-Kommandozeile lädt die Server selbst aus Benutzer-, Projekt- und claude.ai-Konfiguration; der Verwalter zeigt sie im Dialog „MCP-Server“ (`/mcp`), verbindet sie neu und schaltet sie aus. Ausgeschaltet bleibt ein Server für alle Sessions des Vorhabens. Ein Server mit Status „Fehlgeschlagen“ oder „Anmeldung nötig“ zählt als Problem und erscheint als Hinweis in der Eingabeleiste ([ADR 013](decisions/013-mcp-server-im-dialog.md)). |
| **Nebenfrage** | Frage zur Session, die Claude aus dem bisherigen Verlauf beantwortet, ohne dass sie in den Chat wandert; Fork der Session ohne Werkzeuge, nur im Speicher. Gestellt im **Fenster** über der Eingabeleiste (`/btw`, Zeile im `+`-Menü, `Strg+;`), gesammelt im **Reiter** „Nebenfragen“ des Hintergrund-Panels (höchstens 20 je Session, nach dem Beenden der App weg). Im Code `side` ([ADR 044](decisions/044-nebenfragen.md)). |
| **Anmeldung (MCP)** | Die Anmeldung bei einem MCP-Server mit Status „Anmeldung nötig“. „Anmelden“ im Dialog „MCP-Server“ lässt die Kommandozeile die Anmeldeseite nennen, der Core öffnet sie im Standard-Browser (nur `https://`). Eigene Server verbinden sich nach der Anmeldung von selbst, claude.ai-Connectoren nach „Neu verbinden“. Bis die Liste den Server anders meldet oder der Agent endet, gilt die Anmeldung als offen ([ADR 024](decisions/024-mcp-anmeldung.md)). |
| **Hilfsprozess** | Ein kurz gestarteter `claude.exe` (bzw. `codex app-server`), der nur eine einzige Abfrage beantwortet (Kontingent, bei Codex auch Konto und Modelle) und sich danach beendet; gehört zu keiner Session. |
| **Diktieren** | Sprache per Mikrofon aufnehmen und lokal in Text für den Entwurf umwandeln; sendet nie selbst. Im Code `voice` ([ADR 009](decisions/009-sprachdiktat-lokal.md)). Abschnitt — ein Stück der Aufnahme zwischen zwei Sprechpausen, das einzeln erkannt wird. Bedienung: Klick auf das Mikrofon in der Textzeile oder `Strg+M` startet, derselbe Weg beendet; der Text erscheint satzweise schon während des Sprechens an der Cursorstelle, Feld und Senden sind bis zum Ende gesperrt, Esc verwirft das ganze Diktat. |
| **Sprachmodell** | Die lokal gespeicherten Parakeet-Dateien unter `<Benutzerordner>\.verwalter\models\parakeet-tdt-0.6b-v3\`, die das Diktieren braucht; werden einmal auf Klick geladen (rund 670 MB), danach läuft die Erkennung ohne Internet. |
| **Core** | Der Rust-Teil der App (`src-tauri/`): Prozesse, Git, Datenbank, Dateisystem. Die React-Oberfläche spricht nur über Tauri Commands und Events mit ihm. |
| **Übergabe** | Von Haiku aus dem Gesprächstext einer Session geschriebene Zusammenfassung, die der Knopf im Hinweis bei kaltem Cache in den Entwurf der Folgesession setzt; ohne Haiku ein Auszug aus erster Nachricht und letzten Beiträgen ([ADR 051](decisions/051-uebergabe-bei-kaltem-cache.md)). Nicht zu verwechseln mit der Einstiegszeile, die der Agent selbst schreibt. |
| **Einstiegszeile** | Eine Zeile am Ende einer Agenten-Antwort, in zwei Arten: „Weiter: …“ (nächste Session im Vorhaben) und „Neues Vorhaben … : …“ (Auftrag für ein neues Vorhaben); eine Antwort darf mehrere tragen. Die Sidebar zeigt die abgeschlossene Session dann als „wartet auf Wiedereinstieg“; „In neuer Session weiter“ startet daraus die nächste Session, „In neuem Vorhaben starten“ öffnet „Neues Vorhaben“ vorbelegt ([ADR 027](decisions/027-session-uebergabe.md), [ADR 040](decisions/040-automatisch-weiter.md)). In einer Station einer Umsetzung wird sie weder erkannt noch automatisch gesendet. |
| **Automatisch weiter** | Schalter je Vorhaben (Standard aus): nach einer fertigen Antwort mit genau einer „Weiter:“-Zeile startet der Verwalter nach 10 Sekunden Countdown selbst die nächste Session, mit dem Modell aus der Zeile und der Zeile als erster Nachricht. Hält an bei 🔴 in der Antwort, einer Frage am Ende, dem Wort „Merge“, mehreren „Weiter:“-Zeilen, einer schon wartenden neuen Session und nach 6 automatischen Starts in Folge; der Grund steht unter der Antwort. Countdown und Kettenzähler leben nur im Speicher ([ADR 040](decisions/040-automatisch-weiter.md)). Für Stationen einer Umsetzung gilt stattdessen deren eigener Schalter. |
| **Umsetzung** | Ein Plan im Verwalter, als Phasen mit Stationen angelegt über das Werkzeug `implementation_create`; der Verwalter startet jede Station als eigene Session und zeigt den Ablauf als Zeitleiste mit Kartei. Höchstens eine unfertige je Vorhaben. Im Code `implementation` ([ADR 048](decisions/048-umsetzung.md)). |
| **Abbrechen (Umsetzung)** | Beendet eine Umsetzung vorzeitig: sie gilt als abgeschlossen, nichts startet mehr, eine neue Umsetzung im Vorhaben ist möglich; Phasen, Stationen, Verlauf und Sessions bleiben. Gesperrt, solange eine Station arbeitet. **Löschen** entfernt danach (oder bei nie begonnener Umsetzung) Phasen, Stationen und Verlauf, die Sessions bleiben ([ADR 060](decisions/060-umsetzung-abbrechen-und-loeschen.md)). |
| **Anfrage zum Abbrechen** | Ein Agent bittet per `implementation_cancel` darum, die Umsetzung abzubrechen (und zu löschen); bis der Benutzer bestätigt oder verwirft, startet keine Station. |
| **Phase (Umsetzung)** | Abschnitt einer Umsetzung mit Schlüssel (`1`, `2a`), Titel, Beschreibung und Stationen; Phasen derselben Welle laufen gleichzeitig. |
| **Modell-Chip** | Chip oben rechts auf der Stationskarte: Modell und Denkaufwand. Vor dem Start der Plan der Station (gestrichelt), danach die Werte der Session; ein Klick öffnet das Modell-Menü des Chats. |
| **Station** | Ein Schritt einer Phase — Test, Umsetzung, Review, Fix-Runde, Gesamt-Review, Merge, Abnahme —, der als Session läuft; ihr Zustand ist der der Session; fertig heißt per `implementation_complete_station` gemeldet, Stationen „durch dich“ per Knopf „Erledigt“. Aktive Stationen erscheinen in der Sidebar. Stationen laufen mit dem schlanken Ausgabestil `station`, wenn er installiert ist. |
| **Aktive Station** | Station in einem Zustand aus `LIVE_STATES` (bereit, startet gleich, startet, läuft, wartet auf Skript, fragt dich, wartet auf dich, Fehler); steht als Zeile in der Sidebar unter ihrer Umsetzung, bei zugeklapptem Vorhaben nur, wenn sie auf dich wartet ([ADR 056](decisions/056-stationen-in-der-sidebar.md)). Draußen bleiben „wartet“ (noch nicht dran) und „fertig“. |
| **Rückweg-Leiste** | Schmale Leiste unter der Kopfzeile im Chat einer Station: Rückweg zur Umsetzung und ‹ › zur vorigen bzw. nächsten aktiven Station in Plan-Reihenfolge. Sessions, die keine Station sind, haben sie nicht. |
| **Warteliste** | Sessions und Stationen, die auf dich warten, in der Reihenfolge von `Ctrl J`: erst die mit offener Frage, dann die „wartet auf dich“, jeweils die am längsten wartende zuerst. Eine Station mit Session steht nur einmal drin. Wird bei jedem Druck neu berechnet, nicht gespeichert ([ADR 056](decisions/056-stationen-in-der-sidebar.md)). |
| **Welle** | Phasen mit derselben Wellennummer, die zugleich starten; die Phase danach wartet auf alle. |
| **Lagebericht** | Programmatischer Stand einer Umsetzung als Text: Phasen, Stationen, offene Frage, Plan-Änderungen, geänderte Dateien; hängt an jeder Rückfrage und steht hinter dem Knopf „Lagebericht“. |
| **Rückfrage (Umsetzung)** | Reguläre Session im Vorhaben mit dem Lagebericht als Anhang, zum Lesen, Erklären und Umplanen; ändert keinen Code — eine Regel für den Agenten, keine Sperre. Nicht zu verwechseln mit der Rückfrage des Agenten (AskUserQuestion). |
| **Plan-Änderung** | Vorschlag aus einer Session über `implementation_set_phases` mit der vollständigen Liste der kommenden Phasen, vorn wahlweise begonnene Phasen mit neuen offenen Stationen; wirkt erst nach „Übernehmen“ auf der Karte „Plan ändern?“; neu, vorgezogen, entfallen, geändert. Solange er offen ist, startet keine Station, die er ersetzen würde ([ADR 059](decisions/059-begonnene-phase-umplanen.md)). |
| **begonnen** | Eine Station hat begonnen, sobald sie eine Session hat oder fertig gemeldet ist; dann ändert keine Plan-Änderung sie mehr. Eine Phase hat begonnen, sobald eine ihrer Stationen begonnen hat; ihre noch nicht gestarteten Stationen bleiben umplanbar ([ADR 059](decisions/059-begonnene-phase-umplanen.md)). |
| **Prompt-Cache** | Claude hält den bisherigen Verlauf einer Session nach jeder Antwort eine Zeit lang bereit (gemessen 1 Stunde, sonst 5 Minuten); die nächste Nachricht liest ihn dann günstig, statt ihn neu zu schreiben. Gilt nur für ein Modell; abgelaufen, nach einem Modellwechsel oder nach einer Zusammenfassung ist er „kalt“. Im Code `prompt_cache` ([ADR 033](decisions/033-warnhinweise.md)). |
| **Hinweis (Verlauf)** | Zeile im Chat-Verlauf, die festhält, was Claude oder der Verwalter getan hat, ohne Nachricht zu sein: Zusammenfassung, Modellwechsel, Modell-Ausweichen, Moduswechsel, Hinweis von Claude Code, Abschluss einer Antwort. Im Code `ChatEntry::Notice` ([ADR 033](decisions/033-warnhinweise.md)). |
| **Modell-Ausweichen** | Claude wechselt nach einer Markierung durch den Sicherheitsfilter selbst auf ein anderes Modell; die Eingabeleiste zeigt das Ersatzmodell, bis der User ein Modell wählt oder der Agent neu startet. Im Code `fallback_model` ([ADR 033](decisions/033-warnhinweise.md)). |
| **Zusammenfassung (Verlauf)** | Claude ersetzt den bisherigen Verlauf durch eine Kurzfassung, von Hand (`/compact`) oder automatisch kurz vor vollem Kontext; danach kennt der Agent Einzelheiten nur noch aus der Kurzfassung. In Stationen fasst Claude automatisch ab der Schwelle aus den Einstellungen zusammen ([ADR 058](decisions/058-auto-zusammenfassen-in-stationen.md)). Nicht zu verwechseln mit dem TL;DR. |
| **Werkzeug-Detail** | Eingabe und Ausgabe eines Werkzeug-Aufrufs des Hauptagenten, gespeichert je Aufruf und erst beim Aufklappen der Zeile im Chat geladen; Eingabe höchstens 32 KiB, Ausgabe höchstens 128 KiB, Kürzung wird angezeigt ([ADR 042](decisions/042-werkzeug-details.md)). |
| **Ohne Fundstelle** | Angabe in einer Antwort des Agenten (Pfad, Datei:Zeile, Zahl ab zwei Ziffern), die in keiner Werkzeug-Ausgabe derselben Antwort und nicht in der Nachricht des Nutzers vorkommt; im Verlauf gepunktet unterstrichen ([ADR 036](decisions/036-ohne-fundstelle.md)). |
| **Einstellungs-Kategorie** | Eine der vier Gruppen in der Leiste links auf der Einstellungsseite: Allgemein, Agent, Skills & Umgebung, App. Jede enthält Abschnitte mit Zeilen; der Katalog `settingsCatalog.ts` legt fest, was wohin gehört ([ADR 054](decisions/054-einstellungen-kategorien-und-suche.md)). |
| **Portable** | Die lose `verwalter.exe` ohne Installer; ein Update ersetzt sie am selben Pfad ([ADR 041](decisions/041-app-update.md)). |
| **Prüfsumme** | SHA-256 einer Release-Datei, von GitHub je Datei genannt; ohne Treffer wird nichts installiert ([ADR 041](decisions/041-app-update.md)). |
| **Schreib-Ordner** | Ordner, in dem eine Session tatsächlich schreibt: ihre benutzten Ticket-Worktrees und der Haupt-Checkout, wenn sie dort Dateien geändert hat ([ADR 037](decisions/037-parallele-sessions.md)). |
| **Master-Ordner** | Frei gewählter Ordner mit den Originalen von Skills, Befehlen, Ausgabestilen und `CLAUDE.md`; der Verwalter vergleicht `~\.claude` damit und spiegelt auf Klick ([ADR 038](decisions/038-umgebung.md)). |
| **Spiegeln** | Kopiert aus dem Master-Ordner, was dort neuer ist oder lokal fehlt; löscht nie ([ADR 038](decisions/038-umgebung.md)). |
