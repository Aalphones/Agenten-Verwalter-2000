Artefakte für alle Dateitypen

Was sich als Artefakt anbietet, wie jeder Typ angezeigt wird und wie die Liste nach der Session gruppiert wird, die ein Artefakt angelegt hat. Stand: Entwurf, noch kein Plan.

Ausgangslage im Code

Liste nimmt nur HTML

Die Liste lässt nur .html/.htm direkt im Ordner .artefakte durch. Alles andere gilt als Zubehör einer Seite.

Server kann mehr

Der Artefakt-Server liefert Bilder, Videos, Schriften, CSS, JS und JSON schon heute korrekt aus. PDF, Audio, YAML und weitere Typen kennt er noch nicht.

Session-Zuordnung existiert

Jedes Artefakt trägt schon die Session, die es zuletzt per Werkzeug geschrieben hat. Die Liste zeigt sie nur als Meta-Zeile, flach nach Datum sortiert.

Gruppierung nach Session

Die Liste im Reiter bekommt einen aufklappbaren Abschnitt je Session des Vorhabens. Die eigene Session steht oben und ist hervorgehoben, danach folgen die anderen Sessions, sortiert nach ihrem neuesten Artefakt. Am Ende kommt „Ohne Zuordnung“ für Dateien, die per Shell oder von Subagenten geschrieben wurden.

Leitplanken

Sicherheit: nichts davon im Fenster der App rendern. Markdown kann HTML enthalten, SVG kann Skripte enthalten. Im App-Fenster hätte das Zugriff auf die Befehle der App. Deshalb liefert der Artefakt-Server zu jedem Typ eine kleine Betrachter-Seite, die im selben abgeschotteten Rahmen läuft wie heute die HTML-Artefakte. Die Kommentar-Brücke funktioniert damit für alle Typen gleich.
Bibliotheken aus dem Netz, Rohtext als Rückfall: Markdown, Syntaxfarben, PDF und Diagramme laden ihre Bibliothek mit fester Version und Prüfsumme von einem CDN. Grund: Das App-Update tauscht nur die exe, gebündelte Dateien daneben kämen nicht mit, und in die exe eingebaut würden sie jede Version um mehrere MB aufblähen. Ohne Netz zeigt jeder Betrachter den Rohtext.
Festgelegt: welcher Ordner ist Zubehör? Ein Unterordner ist Zubehör, wenn sein Name mit _ beginnt, er so heißt wie eine HTML-Datei daneben oder eine HTML-Datei auf ihn verweist. Jeder andere Unterordner wird ein Artefakt. Die Anweisung an den Agenten nennt die _-Regel.
Neue Anweisung an den Agenten: Der Text im Systemprompt („schreibe es als eigenständige HTML-Datei“) wird erweitert: Bilder, PDFs, Markdown und Daten dürfen direkt als Artefakt abgelegt werden, HTML bleibt die Wahl für alles Interaktive. Gleiches gilt für die Anweisung an Codex.

Vorgeschlagene Stufen

  1. Grundgerüst + Gruppierung: Liste nimmt alle Dateien und Ordner, Typ-Erkennung, Abzeichen, Gruppierung nach Session (inkl. Spalte „zuerst geschrieben“), Betrachter-Rahmen, Rest-Karte, Bild, Video, Audio, Quelltext, Text/Log.
  2. Lesbare Dokumente und Daten: Markdown, JSON, YAML, CSV.
  3. Größere Brocken: PDF, Ordner und Website-Ordner, Mermaid, JSON Lines, TOML/INI/.env, XML, Diff.
  4. Bei Bedarf: Excel, SQLite, Graphviz, Excalidraw, 3D, Zip, Office-Karte.

Jede Stufe ist für sich nutzbar. Die Architektur-Entscheidung 026 bekommt einen Nachfolger, der die Erweiterung festhält.
