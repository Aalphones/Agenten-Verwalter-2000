# FINDINGS — Parakeet statt Whisper

Format: `- [ ] → Phase N: <Erkenntnis>` (offen) bzw. `- [x] …` (erledigt). Wer eine Erkenntnis findet, die eine andere Phase betrifft, trägt sie hier mit Ziel-Phase ein; wer eine Phase beginnt, liest zuerst die Einträge mit seiner Nummer.

- [ ] → Phase 4: Bauvoraussetzung Windows (gelöst durch Nachinstallieren von MSVC 14.44 in den VS 2022 Build Tools; gebaut wird mit `VsDevCmd.bat -arch=amd64` von VS 2022). `ort-sys` 2.0.0-rc.15 lädt ein fertig gebautes ONNX Runtime 1.31.0 (cdn.pyke.io, statisch gelinkt) herunter. Es braucht die vektorisierten STL-Funktionen (`__std_find_end_1`, `__std_max_element_f`, `__std_remove_8` …) eines neueren MSVC-Toolsets: mit VS 2019 (14.29) und mit VS 2022 Build Tools in Toolset 14.38 scheitert der Link mit LNK2019 (42 offene Symbole). Doku und Prüfkette müssen ein aktuelles v143-Toolset nennen; `vcvars64` von VS 2019 reicht nicht mehr.
- [x] → Phase 2: Ordner-Layout (A) ist laut Quelltext ladbar: `ParakeetTDTModel::find_encoder` sucht `encoder-model.onnx`, `encoder.onnx`, `encoder-model.int8.onnx`, `find_decoder_joint` sucht `decoder_joint-model.onnx`, `decoder_joint-model.int8.onnx`; int8 ist auf der CPU zulässig. Laufzeitbeleg: lädt und erkennt mit den drei Dateien unter ihren Originalnamen, Layout (B) nicht nötig.
- [x] → Phase 2: Thread-Zahl einstellbar über `parakeet_rs::ExecutionConfig::new().with_intra_threads(n)` (Standard 4, `inter_threads` 1). Die Probe setzt wie Whisper `min(Kerne, 8)`.
- [x] → Phase 2: Signaturen (kompiliert in `examples/parakeet-probe.rs`): `ParakeetTDT::from_pretrained<P: AsRef<Path>>(path: P, config: Option<ExecutionConfig>) -> parakeet_rs::Result<ParakeetTDT>`; `Transcriber::transcribe_samples(&mut self, audio: Vec<f32>, sample_rate: u32, channels: u16, mode: Option<TimestampMode>) -> Result<TranscriptionResult>` (Trait `parakeet_rs::Transcriber` muss importiert sein; Name kollidiert mit unserem `Transcriber`, also `as _`). `audio` wird als `Vec` übernommen, also kopieren. `ParakeetTDT: Send` (belegt per `assert_send`).
- [x] → Phase 2: Ohne ONNX-Umgebung lädt nichts: `ExecutionConfig::new().with_environment(parakeet_rs::ort::init().build()?)` ist Pflicht, sonst `Error::Config("ONNX Runtime needs an environment …")`. Die README der Crate verschweigt das.
- [x] → Phase 2: Ladezeit des Modellsatzes 3,5–4,0 s (Whisper 0,2 s), Spitzen-Arbeitsspeicher 685–757 MB (Whisper 518 MB). Das Modell einmal laden und halten, wie heute den Whisper-`Transcriber`; das erste Diktat nach dem Start wartet die Ladezeit ab.

- [ ] → Phase 4: Herkunft ONNX Runtime: `ort-sys` lädt beim Bau `ms@1.31.0/x86_64-pc-windows-msvc+directml.tar.lzma2` von cdn.pyke.io (für Windows x64 gibt es nur Varianten mit DirectML) und linkt `onnxruntime.lib` statisch (360 MB Bibliothek, die Probe-exe mit Whisper und ONNX Runtime hat 25 MB). Die exe importiert zusätzlich `directml.dll`, `d3d12.dll`, `dxgi.dll` sowie `MSVCP140.dll`/`MSVCP140_1.dll`. `directml.dll` kam beim Messlauf aus `System32` (10 MB, Windows-Bestand); `ort-sys` kopiert eine neuere `DirectML.dll` (18,5 MB) nach `target/release/`. Für den Installer klären: diese DLL mitliefern oder auf die von Windows setzen. Die Größe der App-exe vor und nach dem Umbau in Phase 2 messen.
