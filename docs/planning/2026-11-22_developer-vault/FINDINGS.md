# Findings

Erkenntnisse während der Umsetzung, die eine spätere Phase betreffen. Format: `- [ ] → Phase N: <Erkenntnis>`; erledigt wird abgehakt.
- [ ] → Phase 4 (offen): Bild-Antwort von `vault_get` in einer echten Session NICHT geprüft — dafür braucht es eine neu gebaute App mit eingeschaltetem Vault und eine Session, die `vault_get` auf eine PNG-Datei ruft. Die Antwort ist nach MCP-Schema gebaut (`content: [{type:"text"}, {type:"image", data, mimeType}]`, `rpc.rs`); ob die Claude-Kommandozeile das Bild dem Modell zeigt, ist unbelegt. Beim ersten Lauf in der echten App: Agent eine PNG laden und beschreiben lassen, Ergebnis hier eintragen. Ebenso `mcp-probe list` (zeigt `vault_search`/`vault_get` nur bei eingeschaltetem Vault) gegen die laufende App.
- [ ] → Phase 5: `search::search(app, &VaultQuery)` liefert `VaultSearchResult`; `any_term: true` ist für die Suche des Stationsauftrags gedacht. Fehlt der Vault, kommt `CommandError::Internal` mit dem fertigen Satz (`search::NOT_SET_UP` bzw. Status-Meldung) — der Stationsauftrag lässt die Zeile dann weg.
- [x] → Phase 6: Bindings `VaultQuery`, `VaultHit`, `VaultSearchResult` sind erzeugt; Markierungen im `snippet` sind U+E000 (Anfang) und U+E001 (Ende). `VaultQuery.limit` wird im Core auf 1–50 begrenzt (Suchdialog), das Werkzeug erlaubt 1–20.
- [ ] → Phase 4 (Abweichung): Zu großes Bild (über 5 MiB) liefert „Bild (<Größe>) — größer als 5 MiB, wird nicht geladen.“ statt des Binärdatei-Satzes; ohne Überschrift entfällt „Abschnitt „…“,“ in der Trefferzeile.
