# Findings — Autarker Agent

Erkenntnisse während der Umsetzung, je eine Zeile, getaggt mit der Phase, die sie aufgreift: `- [ ] → Phase N: <Erkenntnis>`. Erledigt → `[x]`.

- [x] → Phase 2: `interrupt` meldet `result_aborted` sofort und hängt `[Request interrupted by user]` (Rolle `user`) **sofort** ans Transkript (`Session::interrupt`); der Arbeits-Thread läuft weiter, bis er den Abbruch merkt, und erst danach beginnt der nächste Turn (`ActiveTurn.is_aborted`). Schreibt in Phase 2 der Arbeits-Thread Werkzeug-Ergebnisse ins Transkript, käme der Marker vor die `tool`-Nachrichten und das Format bräche (assistant mit `tool_calls` ohne direkt folgende Ergebnisse). Lösung dort: alle Transkript-Schreibzugriffe eines Turns an einer Stelle — z. B. der Thread gibt seine Nachrichten zurück und die Hauptschleife hängt sie samt Marker in der richtigen Reihenfolge an, oder der Marker kommt erst, wenn der Thread zurück ist.
- [x] → Phase 2: `request_messages` legt aufeinanderfolgende `user`-Nachrichten zu einer zusammen (`content::merge_user`), weil manche Chat-Vorlagen zwei in Folge ablehnen; `tool`-Nachrichten sind davon nicht berührt.
- [x] → Phase 3: Die Session führt noch keinen Modus — `set_permission_mode` prüft den Wert nur. Feld `mode` in `Session` ergänzen (Start aus `args.mode`, `args::mode_from_cli` für die Steueranfrage). Eingehende `control_response`-Zeilen werden bisher still überlesen (`handle_line`).
- [x] → Phase 3: Die Pfadgrenze prüft heute jedes Werkzeug selbst (`tools::checked_path` → Fehler „Pfad außerhalb …“). Für die Rückfrage muss die Entscheidung vor `tools::run` fallen (`turn::run_tool`): Pfad aus `file_path`/`path` über `paths::resolve` + `Roots::access` holen, bei `Outside` `can_use_tool` stellen und nach „allow“ das Werkzeug ohne die Grenze laufen lassen (z. B. Flag im `ToolContext` für diesen einen Aufruf). `Roots` liegt im `ToolContext` hinter dem Mutex der Session.
- [x] → Phase 3: Esc mitten in einer Werkzeug-Runde ist ungeprüft — zwei Treiber-Läufe unterbrachen noch die Modellanfrage. Der Bash-Test `sleep 30` aus AK 7 trifft genau diesen Fall: danach im Transkript prüfen, dass `[Request interrupted by user]` **hinter** dem `tool`-Eintrag steht. *(Phase 3: nicht gefahren, als Prüfschritt in Smoke 1 der README übernommen.)*
- [x] → Phase 5: TL;DR in „Autark“: `start_session_tldr`/`start_project_tldr` rufen `find_claude()` **vor** `ask_haiku` — ohne installierte Claude-Kommandozeile kommt „Claude nicht gefunden“ statt des Satzes aus `ask_haiku`. Beim Bau des Druckmodus die Programmwahl wie in `start_process` vorziehen.
- [ ] → Phase 6: **Kontrakt geändert durch ADR 022** (parallel gebaut, Commit „App gibt dem Agenten den Scratchpad-Ordner vor“): Der Verwalter legt `<Workspace>\.scratchpad\<session-id>` selbst an und nennt ihn jedem Agenten per `--append-system-prompt`; `AgentEvent::ScratchpadDir` wird ignoriert. Die Phasen-Datei plant noch `%USERPROFILE%\.verwalter\agent\<id>\scratchpad` und `scratchpad_path` in `init` — das entfällt. Der Agent braucht den Pfad aber maschinenlesbar für `<scratchpad>\tasks\<task-id>.output`: den Pfad nicht aus dem Prompt-Text fischen, sondern im Core zusätzlich übergeben (z. B. Umgebungsvariable in `local::apply` bzw. `SpawnOptions.scratchpad`). README „Festgelegte Entscheidungen“ ist schon nachgezogen. Phase 1 wertet `--append-system-prompt` bereits aus (hängt ihn an den Systemprompt).
- [ ] → Phase 7: Eine Anfrage mit unbekanntem Modellnamen beantwortete LM Studio erst nach 132 s, dann mit dem geladenen Modell. Hypothese (nicht belegt): sie wartete hinter einer vorher abgebrochenen Anfrage — ob LM Studio nach dem Schließen der Verbindung aufhört zu rechnen, ist offen. Wichtig für die Zeitgrenze der Modellanfrage.
- [x] → Phase 4: `permissions::decide` lässt unbekannte Werkzeuge nachfragen. `Skill` beim Einbau in die Nur-Lese-Liste (`Allow`) aufnehmen — sonst fragt jeder Skill-Aufruf nach.
- [ ] → Phase 6: dito `TaskStop` (`Allow`); `Bash`/`PowerShell` mit `run_in_background` laufen über dieselbe Rechte-Prüfung wie heute. `shell::wait_for` beendet bei Esc den ganzen Prozessbaum — Hintergrundprozesse dürfen dort nicht hinein.
- [ ] → Phase 7: Werkzeuge eines Subagenten brauchen denselben Weg in `turn::run_tool` (Hooks, `decide`, `can_use_tool`); die Antwort kommt über den `answers`-Kanal des Turns, den die Hauptschleife füttert — Subagenten-Threads brauchen einen Anteil daran (z. B. Verteilung nach Request-ID).
- [ ] → Vault: Windows-Topic (PowerShell 5.1) — Symptom: Fehler eines Kindprozesses `powershell.exe` kommen als `#< CLIXML <Objs …>` auf stderr · Ursache: Aufruf mit `-EncodedCommand` (auch mit `-OutputFormat Text`, `-InputFormat None`) · Fix: `-Command <text>` verwenden; Quoting übernimmt die MSVC-Argumentregel (`\"`).
- [x] → Phase 2 (vom Benutzer aus Phase 9 vorgezogen, Checkliste dort ergänzt): AK 2 (keine `claude.exe` in „Autark“): Die Einstellungsseite liest das Claude-Konto unabhängig von der Betriebsart (`AccountRow` → `account_load` → `claude auth status --json`). In „Autark“ startet das eine `claude.exe`, sobald die Einstellungen offen sind.
- [x] → Phase 5: Der Systemprompt ist nach Phase 4 einmal beim Start gebaut (`Session.system_prompt`) und ~13 500 Token groß (gemessen: `CLAUDE.md` 6 300, drei Einbindungen 3 100, Rest Grundregeln, Style, 26 Skills) — rund ein Fünftel eines 64k-Fensters, ohne Verlauf. `prompt::estimated_tokens` und `MemoryFile.tokens` liefern die Zahlen für die Kontext-Aufschlüsselung (`get_context_usage`); Verdichten verändert nur das Transkript, nie diesen Prompt.
