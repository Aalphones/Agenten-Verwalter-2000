# Findings — Meilenstein 2a Durchstich & Chat

Erkenntnisse aus der Umsetzung, getaggt nach Ziel-Phase:

```text
- [ ] → Phase N: <Erkenntnis>
```

- [x] → Phase 2: `ToolFinished` kommt auch für `tool_use_id`s ohne vorheriges `ToolStarted` — `TodoWrite` und `AskUserQuestion` erzeugen kein `ToolStarted`, ihr `tool_result` aber ein `ToolFinished`. Unbekannte IDs still ignorieren, nicht als Fehler behandeln.
- [x] → Phase 2: `QuestionAsked.input` je `request_id` aufbewahren — `protocol::allow` braucht es als `updatedInput` (bei `AskUser` zusätzlich `answers: { "<question>": "<label>" }`, siehe Wissensdatei).
- [x] → Phase 2: `on_output` läuft auf zwei Threads gleichzeitig (stdout, stderr). `Stderr`-Zeilen können nach `Exited` eintreffen — das Session-Protokoll muss sie danach noch annehmen, der Status darf davon nicht mehr abhängen.
- [x] → Phase 2: `Exited` kommt erst nach Dateiende auf stdout. Erbt ein vom Agenten gestarteter Kindprozess dessen stdout, kann das Dateiende später kommen als das Prozessende (nicht geprüft) — fällt im Smoke „Absturz“ auf, falls der Fehlerkasten ausbleibt.
- [x] → Phase 3: `session_create` liefert die `SessionSummary` im Status `starting` — dafür gibt es kein `session://changed` (das kommt erst mit `running`). Der Store muss die Rückgabe von `createSession` selbst einfügen, nicht auf das Ereignis warten.
- [x] → Phase 4: Auch im Modus „Auto“ kommt für `Write` eine Rechte-Abfrage (`questionKind: permission`, Frage „Claude möchte Write ausführen: <Pfad>“). Der Kasten muss im Chat auch in Auto vorkommen, nicht nur in Manuell.
- [x] → Phase 4: Wird eine offene Rechte-Abfrage durch Pause abgelehnt, zeigt die Werkzeug-Zeile `failed`, nicht `interrupted` (die Absage kommt als Fehler-Ergebnis vor der Unterbrechung); die Frage trägt die Antwort „Pausiert“. Nur ein laufender Aufruf ohne Rückfrage wird `interrupted`.
- [x] → Phase 4: Eine Frage mit gesetzter `answer` ist erledigt, egal wie sie erledigt wurde: „Blau“ (Antwort), „Erlaubt“, „Abgelehnt: …“, „Pausiert“, „Abgebrochen“, „Nicht beantwortet“ (Absturz/Fehler). Die Oberfläche zeigt `answer` als Text, die Knöpfe nur bei `answer === null`.
- [ ] → Phase 6: `chat_send` bei offener Rückfrage beantwortet die älteste (AskUser: derselbe Text für jede Frage; Rechte-Abfrage: Ablehnung mit dem Text). Der Eingabe-Platzhalter sollte das sagen. `session_pause` und `session_cancel` sind bei bereits beendetem Prozess still (kein Fehler); `session_set_model`/`set_mode` schreiben nur an einen lebenden Agenten, speichern sonst den Wert für den nächsten Start.
- [ ] → Phase 6: Der Esc-Listener des Chats muss `event.defaultPrevented` prüfen und dann nichts tun — `Popover` verbraucht Esc in der Capture-Phase per `preventDefault`. `Popover` gehört als Kind in ein `position: relative`-Element, das auch den Auslöser enthält (Auslöser-Klick zählt als „innen“); `ModelMenu` braucht dort `placement="above"` und eine eigene `note`.
- [x] → Phase 4: `src/app/App.tsx` hat für den Chat den leeren Platzhalter `<div className="app__content" />` unter `SessionHeader` — dort den Chat einhängen.
- [ ] → Vault: sprachen/rust — Sperre lebt länger als gedacht · Ursache: Temporäre Werte im `match`-Kopf (`match mutex.lock().x() { … }`) leben bis zum Ende des ganzen `match`, auch in Edition 2024 — ein `sleep` in einem Arm hält die Sperre mit · Fix: Ergebnis erst in eine eigene Variable (`let status = mutex.lock().x();`), dann `match status`.
- [ ] → Phase 5: Seit Phase 4 läuft jede Komponenten-CSS durch `postcss-nested` (`vite.config.ts`) — vorher waren alle `&__x`/`&--x`-Selektoren im Build kaputt (natives Nesting hängt nichts an). Markdown-Styles dürfen `&__x` benutzen; nach dem Bauen im CSS unter `dist/assets/` prüfen, dass kein Selektor mit `__` oder `--` beginnt. Selektoren mit zwei `&` ausschreiben.
- [ ] → Phase 5: `TextBlock` ist ein `<p>` mit `white-space: pre-line`; für Markdown wird er ein Container (`<div>`), `pre-line` muss dann weg (sonst doppelte Umbrüche zwischen Absätzen). Die Blöcke stehen in einer virtualisierten Liste — Höhenänderungen nach dem ersten Rendern (z. B. nachgeladene Syntaxfarben) misst `measureElement` nach, verschieben aber kurz die Ansicht.
- [ ] → Phase 6: `ChatView` hält die Einträge (`useChatEntries`) und hat den leeren Platz `chat-view__composer` für die Eingabeleiste. Die älteste offene Rückfrage für den Eingabe-Platzhalter lässt sich dort aus `entries` ableiten (`kind === 'question' && answer === null`). Die Ziffern-Tasten 1–9 im Verlauf ignorieren Ereignisse aus `input`/`textarea`/`[contenteditable]` und mit `defaultPrevented` — das Eingabefeld braucht dafür nichts zu tun.
- [ ] → Plan-Ende (Smoke): Virtualisiert wird je Block, nicht je Werkzeug-Zeile. 80 Read-Aufrufe ohne Text dazwischen sind **eine** Werkzeug-Gruppe — aufgeklappt stehen dann alle 80 Zeilen im DOM. AK 6 der Phase 4 greift nur, wenn Text, Gedankengang o. Ä. die Aufrufe in viele Gruppen teilt. `@tanstack/react-virtual` 3.14.13.
- [ ] → Vault: frameworks/css-architecture — BEM-Verschachtelung im Build kaputt · Ursache: natives CSS-Nesting kennt kein Anhängen an den Elternnamen; `&__name` wird zu `__name.block` (Typ-Selektor), Lightning CSS/Browser übernehmen das still, kein Fehler, keine Warnung · Fix: `postcss-nested` (Sass-Semantik) vor dem Bündeln, oder Selektoren ausschreiben; Prüfung: gebautes CSS auf Selektoren mit führendem `__`/`--` durchsuchen.
