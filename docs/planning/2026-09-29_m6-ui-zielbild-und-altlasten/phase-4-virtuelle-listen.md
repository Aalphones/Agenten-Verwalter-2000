## Abnahmekriterien

1. Sidebar, „Prozesse“, „Subagenten“ und Scratchpad rendern nur sichtbare Zeilen plus Überhang (`overscan` 12); das Aussehen bleibt pixelgleich zu vorher (gleiche Abstände zwischen Gruppen und Zeilen, gleiche Leer-Sätze).
2. Die Sidebar-Liste scrollt senkrecht, wenn sie länger als der Platz ist.
3. Tab läuft weiter durch alle Zeilen einer Liste: fokussiert Tab eine Zeile am Rand des gerenderten Bereichs, scrollt sie ins Bild und die nächsten Zeilen erscheinen.
4. Sidebar: Umbenennen (Doppelklick, F2, Rechtsklick, ⋯, `/rename`) funktioniert wie vorher für Vorhaben und Sessions; startet es für eine Zeile außerhalb des sichtbaren Bereichs, scrollt die Liste zu ihr (`scrollToIndex`, `align: 'auto'`), bevor das Feld den Fokus bekommt. Auf- und Zuklappen eines Vorhabens lässt die Zeilen darunter erscheinen bzw. verschwinden, ohne dass die Liste springt; die linke Linie der aufgeklappten Sessions bleibt über alle ihre Zeilen durchgehend.
5. Hintergrund-Panel: Auswahl per Klick, „Im Chat besprechen“, Öffnen eines Eintrags über eine Verlaufszeile (`openItem`) scrollen die gewählte Zeile ins Bild.
6. `pnpm check` grün.

## Checkliste

### Sidebar

- [x] **Umbau von `SidebarProject`:** heute rendert das Bauteil die Vorhaben-Zeile und darunter die Liste seiner Sessions. Eine virtuelle Liste braucht jede Zeile einzeln — `SidebarProject` rendert danach **nur noch die Vorhaben-Zeile** (Props ohne `sessions`, `activeSessionId`, `onSelectSession`; `isExpanded` bleibt für Chevron und `aria-expanded`), die Session-Zeilen rendert die Sidebar als eigene Zeilen über `SidebarItem`. Wo `SidebarProject.css` die Einzug-/Linien-Regeln der Session-Liste (`margin-left: 26px`, `padding-left: 6px`, linke Linie) trägt, wandern sie an die Session-Zeile: jede Session-Zeile bekommt dieselbe Linie (`border-left`), und weil die Zeilen ohne Lücke aneinanderstoßen (Abstand 0, kein `gap`), ergibt das wieder eine durchgehende Linie; der Abstand 4 px unter der Liste wird `padding-bottom` der letzten Session-Zeile eines Vorhabens (`isLast`).
- [x] `src/app/buildSidebarRows.ts`: `export type SidebarRow = { kind: 'group'; key: string; group: SessionGroup; count: number; isFirst: boolean } | { kind: 'project'; key: string; project: ProjectSummary; sessions: readonly SessionSummary[] } | { kind: 'session'; key: string; session: SessionSummary; isLast: boolean }`; `export function buildSidebarRows(groups: readonly { group: SessionGroup; projects: readonly { project: ProjectSummary; sessions: readonly SessionSummary[]; isExpanded: boolean }[] }[]): SidebarRow[]` — je Gruppe mit mindestens einem Vorhaben eine Überschriftszeile (`key` = `group:<Gruppe>`, `count` = Anzahl Vorhaben), dann je Vorhaben eine Vorhaben-Zeile (`key` = `project:<id>`) und, wenn `isExpanded`, seine Sessions aufsteigend nach Nummer (`key` = `session:<id>`, `isLast` bei der letzten). Reihenfolge und Gruppierung liefert die Sidebar wie in Phase 3 des Plans „Vorhaben und Sessions“ (`projectGroup`, neueste Vorhaben zuerst); diese Funktion ordnet nur an. Leere Gruppen entfallen wie bisher.
